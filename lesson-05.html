Telegram Learning Lab · Lesson 05

Lesson 5: Let AI write the draft. Keep control of what happens next.

About 95 minutes. In Lesson 4, Rust chose a fixed reply or a handoff. This time you’ll compare a fixed reply with a model-written draft. Your Rust code still decides whether the result goes to review or handoff. Nothing connects to Telegram, and there’s no send function.

1. Learn the moving parts · 15 min

Read or watch 3Blue1Brown’s short LLM introduction. A token is a piece of text. The context is the input the model can use: instructions, facts, and the customer’s question. A prompt tells the model what to do with that input. Notice the difference between predicting a plausible next token and checking that a product claim is true.

2. Compare two replies · 20 min

Use one verified fact from the TeleShelf 0.66.1 release notes: comment rows show the author’s Telegram photo when available and fall back to initials.

Fictional customer: “Some comments show letters instead of faces. Did I turn something off? I’m on 0.66.1.”

Treat that release fact as your fixed reply. Then give the same fact and question to ChatGPT with these instructions: “Write a friendly support draft in two sentences. Use only the supplied fact. If the fact doesn’t answer the question, return HANDOFF. Don’t invent a setting or suggest a fix you can’t verify.”

Compare the replies: Which answers the question more directly? Did the model add any claim the source doesn’t support? For an offline run, write a pretend model draft instead and label it as simulated.

3. Put the draft behind a Rust boundary · 40 min

Extend your Lesson 4 exercise or use a tiny separate Rust module. Keep the model outside the app for now: paste its output into a test fixture. Your function should return either ReviewDraft(text) or HandOff(reason), never a send instruction.

Write tests for an eligible question with a nonblank draft, an explicit HANDOFF, blank output, a simulated model failure, and a question outside the supported topic. Keep the last case as a handoff even if a model offers a confident reply. Run cargo test.

4. Catch one convincing mistake · 20 min

Feed in a bad draft: “Go to Settings → Comments and turn on Show profile photos.” Your code can recognize that it’s nonblank. It can’t establish that the setting exists. As reviewer, reject it and write one plain note: “The draft invented a setting instead of explaining the automatic initials fallback.” Then write the corrected reply.

Done when: your tests pass, you’ve compared both replies, and you can explain why a draft can pass a Rust test and still need your review.
