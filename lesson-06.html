Telegram Learning Lab · Lesson 06

Lesson 6: Give the draft something to cite

About 100 minutes. In Lesson 5, you gave the model one verified fact and reviewed its draft. This time you’ll give it a small TeleShelf FAQ and decide when the evidence supports a reply, when one question would help, and when to hand off. Use fictional tickets only. No Telegram, API key, or send function.

1. Learn the distinction · 15 min

Read “How does RAG work?” in Microsoft’s short RAG overview. Retrieval finds passages; grounding is using those passages to support the answer. Today you’ll choose the passages yourself. Search, embeddings, and vector databases can wait.

A citation gives the reviewer a place to check. It doesn’t prove the passage applies to the customer’s case or supports every claim in the draft.

2. Run four tickets against a two-entry FAQ · 30 min

Use this packet. The version labels describe the evidence for this exercise, not the latest download.

  • PHOTO · TeleShelf 0.66.1 release notes: Comment rows use the author’s Telegram profile photo when available; otherwise they show initials. For this exercise, treat this entry as verified for 0.66.1 only.
  • PLAYBACK · Pinned TeleShelf guide: For an unsupported video format, the player explains the limitation and offers Back to Home. Potentially temporary failures still offer Retry.

Give the packet to ChatGPT with this prompt, or simulate its outputs on paper:

Use only the supplied FAQ. Return DRAFT with one or two sentences and the ID of the passage that supports the answer; CLARIFY with one question if a missing detail would let you use the FAQ; or HANDOFF with a short reason if the answer is outside the FAQ. Don’t invent a setting or diagnose a device from incomplete information.

Try one ticket at a time. Compare the output with these expectations:

  1. “I’m on 0.66.1. Why do some comments show initials?” → DRAFT · PHOTO. Explain the fallback; don’t infer why a specific photo is unavailable.
  2. “The player says Unsupported format. Should I keep pressing Retry?” → DRAFT · PLAYBACK. Explain the message and point to Back to Home.
  3. “My video won’t play. Should I retry?” → CLARIFY. Ask what exact message the player shows.
  4. “Was my refund approved?” → HANDOFF. The FAQ can’t tell you the status of a personal transaction.

3. Put the checks in Rust · 35 min

Extend your Lesson 5 module or run cargo new --lib lesson06 for a separate exercise. Paste the outputs into typed fixtures manually rather than writing a parser. Use Lesson 5’s ReviewDraft and HandOff, and add Clarify. A draft needs nonblank text and a source ID from the packet. A clarification needs a nonblank question. Blank output, failed model calls, and unknown or missing draft IDs go to handoff. None of these outcomes sends anything.

Run cargo test --offline. Test the four cases above, a draft citing PHOTO_99, a draft without a citation, and a simulated model failure. Use a fixture such as Draft { text: "Initials appear when the profile photo isn’t available.", source_id: Some("PHOTO") } and expect ReviewDraft.

4. Break a draft that passes · 20 min

Replay this draft with a real citation: “Go to Settings → Comments and turn on Show profile photos.” [PHOTO]. It can pass the Rust shape checks, but the passage doesn’t support the setting. Reject it and write a corrected reply. Then remove PHOTO from the model’s packet and replay ticket 1. The expected route is now handoff, even though you remember the answer.

Done when: your tests pass and you can explain the difference between a valid citation, an applicable source, and a claim the source actually supports.
